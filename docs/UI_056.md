# MRP 0.5.6 — OEE por turno, metas e histórico

A versão 0.5.6 amplia o monitoramento da 0.5.5 para análise de melhoria contínua.

## Entregas

- snapshots OEE por turno e máquina;
- suporte a turnos que atravessam a meia-noite;
- metas versionadas por planta, centro de trabalho ou máquina;
- precedência de meta: máquina > centro > planta;
- perdas equivalentes de disponibilidade, performance e qualidade;
- Pareto de motivos de parada;
- dashboard histórico com filtro por planta, máquina e intervalo;
- tendência diária de OEE;
- consolidação por máquina e comparação com meta;
- comando para reconstrução histórica diária e por turno.

## OEE por turno

O modelo `OEEShiftSnapshot` utiliza os turnos já cadastrados em `WorkCenterShift`.
A data operacional é a data em que o turno inicia. Se `end_time <= start_time`, o turno termina no dia seguinte.

```bash
python manage.py calculate_oee --plant SP01 --date 2026-08-07 --include-shifts
```

Para reconstruir um intervalo:

```bash
python manage.py calculate_oee_history \
  --plant SP01 \
  --from 2026-07-01 \
  --to 2026-08-07
```

## Metas

`OEETarget` guarda metas de OEE, disponibilidade, performance e qualidade com vigência.
A resolução da meta usa primeiro uma definição específica da máquina, depois do centro e por fim da planta.

As metas podem ser mantidas pelo Django Admin.

## Perdas OEE

Os snapshots preservam três perdas equivalentes em minutos:

- `availability_loss_minutes`: minutos de parada dentro da janela planejada;
- `performance_loss_minutes`: diferença entre tempo operacional e tempo ideal necessário à quantidade produzida;
- `quality_loss_minutes`: minutos de ciclo ideal equivalentes às unidades refugadas.

## Histórico

A tela está disponível em:

```text
/shopfloor/oee/history/
```

Filtros:

- planta;
- máquina opcional;
- data inicial;
- data final.

A interface apresenta KPIs consolidados, tendência diária, perdas, Pareto de paradas, resultado por máquina e snapshots por turno.
